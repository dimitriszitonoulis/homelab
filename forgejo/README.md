# forgejo

## Description

Self hosted alternative to github.
I chose forgejo over gitlab because it is more lightweight,
for example forgejo can use sqlite as a database instead of PostgreSQL.

## 1st deployement

The docker-compose.yml contains the following part:

```yaml
ports:
  - "3000:3000"
  - "222:22"
```

When visiting the web page at http://<server_ip>:3000
for the 1st time there will be a menu with configuration options.

One of them is the port the container will expose for the web ui.
The default one is `3000` which can be changed from the menu.
Write it down as it will be needed by the reverse proxy.
After configuring all the options and entering a config for the reverse proxy,
remove the line `-3000:3000` from `docker-compose.yml`.

## ssh

### Pushing to repo

To push to remote repository you must:

1. Create an ssh key pair.
2. Upload the public key to forgejo.
3. Configure ssh to use the correct key (explained below).

I will not explain how to create an ssh keypair as it is really easy.

### shh config

It is best to create an entry for forgejo in the ssh config (`.ssh/config`) because:

- As all the other services, forgejo runs behind a reverse proxy.
- Forgejo must use a different ssh port than the one used to connect to the server

If no entry is created the ssh links generated by forgejofor
for pushing code to a remote repository will not work,
since ssh will not be able to locate the corresponding key used for authentication.

Paste the following into `~/.ssh/config` of the client machine
(the one trying to push to forgejo):

```bash
Host <my_domain>
  HostName git.mydomain.com
  User git
  IdentityFile /path/to/forgejo/ssh/key
  Port <forgejo_server_ssh_port>
  IdentitiesOnly yes
```

Now the link generated by forgejo will work:
`ssh://git@git.mydomain.com:<ssh_port>/<user_name>/<repo_name>.git`

> [!NOTE]
> The ssh port can be removed from the link as long as it is the same
> as the one in the ssh config.
